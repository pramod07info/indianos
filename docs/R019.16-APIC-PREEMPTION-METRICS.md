# R019.16 — Distinguish APIC IRQ delivery from user preemption

The APIC timer has two independently queryable metrics:

- `x86_64_xapic_timer_irq_count()` — EOI acknowledgements from the APIC handler.
- `x86_64_xapic_timer_preemption_count()` — successful ring-3 frame captures
  that proceed to the scheduler yield path.

The dispatcher records preemption only after `capture(regs, true)` succeeds.
`xapic_preemption_progress()` requires both counters to be nonzero.

The timer stop path now clears its RUNNING flag only after the mapped
registers have been successfully located and masked, avoiding false
software state when hardware access cannot proceed.

## QEMU acceptance

1. APIC IRQ count increases while periodic timer runs.
2. APIC preemption count increases with valid ring-3 execution.
3. At least two runnable tasks alternate without cooperative yields.
4. No PIC IRQ0 count is used as a substitute for APIC IRQ evidence.

These acceptance checks still require execution in QEMU.
