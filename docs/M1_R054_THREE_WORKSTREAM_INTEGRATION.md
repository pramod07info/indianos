# M1 R054 — three kernel/workstation reliability workstreams

Base main: `4d0f7fe6ccf7fd2bfd0997ba19024d08179f3a70` (the R053 merge plus an actual QEMU screenshot archive). One branch, one consolidated integration commit, one draft PR.

1. **M2 package BLOB read/upgrade/rollback authorization:** a long-lived store handle revalidates its cached committed header against the live header before verified reads, stage, and rollback. Stage additionally validates the current package hash before touching the other bank; rollback validates both live headers and payloads. A modified but self-consistent metadata header or altered payload now fails closed, and failed verified reads zero their output. Three new fault/tamper regressions.
2. **M1 supervised restart preparation:** a failed pending replacement can be retried with an unused fresh PID, monotonically increased generation and charged restart budget. Old PID/generation cannot call prepared(). Multi-service preparation retries are fail-atomic with unchanged caller output. Two new regression tests. **Supervisor must revoke the old process, mapping, mailbox and grants before calling retry**; this API is a policy primitive, not a live scheduler wiring claim.
3. **PS/2 auxiliary input reliability:** test-only mouse setup no longer drains primary-keyboard bytes, instead failing safely if the keyboard channel has pending data. Mouse commands handle up to three AUX-owned RESEND responses; no primary-channel ACK impersonation. Two new protocol regressions. This remains a single-BSP, masked-IRQ test driver, not a general production mouse service.

**Scope and truth in reporting:** Three functional workstreams are implemented by the connected coordinator; **zero independent autonomous coding agents were launched**. Do not count CI jobs, docs or fake agent files as coding sessions. No physical disk writes or user-data provisioning.
