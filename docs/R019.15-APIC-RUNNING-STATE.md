# R019.15 — Distinguish APIC setup from running periodic interrupts

The APIC UC mapping/initialization state is not evidence of a running timer.
The kernel now tracks the periodic timer independently:

- Calibrated periodic start marks the timer running after MMIO programming.
- Stop clears running status before masking the timer.
- Masked one-shot calibration refuses to start over a running periodic timer.
- The ring-3 APIC interrupt dispatcher gates preemption on running status,
  not merely the presence of a configured APIC mapping.
- The APIC interrupt counter remains independent of legacy PIC IRQ0.

## Required verification

Run Rust feature-matrix tests and the QEMU kernel boot workflow. A passing
compile is **not** evidence of actual IRQ delivery. Hardware preemption
requires an observed nonzero APIC IRQ counter and ring-3 task alternation.
