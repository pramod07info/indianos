# R019.14 — APIC interrupt accounting and preemption guard

This milestone connects the existing APIC interrupt dispatcher to explicit
hardware readiness and adds separate IRQ-delivery accounting.

- Local APIC EOI increments a saturating APIC-only interrupt counter.
- The ring-3 timer dispatcher refuses to preempt when the APIC timer is not armed.
- PIC IRQ0 counters remain independent; an APIC EOI is never treated as a PIC ACK.
- The APIC IRQ counter can be queried with `x86_64_xapic_timer_irq_count`.

## Validation gate

The kernel CI must compile the timer and user-runtime feature combinations.
QEMU must additionally demonstrate a **nonzero APIC IRQ count**, followed by
two user tasks making progress under timer-driven scheduling, before
hardware preemption can be marked complete.

This commit does not establish that firmware routing, UC MMIO mapping, timer
calibration, or ring-3 preemption are working in QEMU.
